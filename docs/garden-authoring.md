# Digital Garden 運用ガイド（ノウハウ発信の基盤）

このプロジェクトの知見を **Obsidian の Digital Garden** として発信し続けるための仕組み。
「今後も同じ品質で作り続けられる基盤」をここに定義する。

## 全体像
- **唯一の源（source of truth）は このリポジトリの `garden/`**。
- `garden/` は **Obsidian ボールトの Digital Garden フォルダと同じ構成**にする（下記）。
  → だから `garden/` をボールトへコピーしても**重複せず・上書きで・崩れない**。
- 仕組み（この文書・テンプレ・検証スクリプト）は **`garden/` の外**（`docs/`・`scripts/`）に置く。
  → ボールトに混ざらない（`garden/` だけを同期する）。

## フォルダ ＝ 成長段階（Obsidianボールトに準拠）
| フォルダ | 意味 | 使い方 |
|---|---|---|
| `1_Seeds` | 芽・走り書き | 粗いメモ、未検証のアイデア |
| `2_Growing` | 育成中 | 検証済みだがまだ育てる知見（今回の開発ノウハウはここ） |
| `3_Evergreen` | 常緑・安定 | 原則・あまり変わらない土台（夢分析のドメイン知識など） |
| `9_Compost` | 退避 | 古くなった/取り下げた記事 |
| `0_Glossary` | 用語集 | 用語の短い定義 |

ホーム（MOC）の「Dream Analyzer ノウハウ庭.md」は `garden/` 直下に置く。
成長したらフォルダを移すだけでよい（リンクはファイル名で解決されるので**移動しても切れない**）。

## フロントマター（必須）
```yaml
---
dg-publish: true        # これが付いたノートだけ公開される
title: <タイトル>
tags: [dev, ...]        # dev / dream / mcp / ai / ux など
---
```
ホームだけ `dg-home: true` を追加。

## 文体（揃えるための基準）
- **見出し `##` ＋ 短い段落**。1段落は3〜5行まで。
- 要点は**太字**、列挙は箇条書き。冗長にしない。
- 末尾は必ず **`関連: [[...]] / [[...]]`** で他ノートへ繋ぐ（庭の背骨）。
- 文体パターン:
  - **開発の知見**: 問題 → 気づき → やったこと → ハマりどころ → 教訓
  - **夢分析ドメイン**: 枠組み → 要点 → 例 → 読み方
- コードは最小限。「何をしたか」より**「なぜその判断にしたか」**を残す。

テンプレ: [`docs/garden-note-template.md`](./garden-note-template.md)

## ノートの足し方（手順）
1. テンプレをコピーし、`garden/<段階フォルダ>/<タイトル>.md` を作る（ファイル名＝タイトル）。
2. 本文を書き、関連ノートへ `[[wikilink]]` を張る（参照先はファイル名）。
3. 検証: `node scripts/garden-check.mjs`（frontmatter漏れ・リンク切れをチェック）。
4. コミットして push。

> 実運用では、セッションで Claude がこの基準に沿ってノートを生成・検証し、あなたは同期と公開だけでよい。

## ボールトへ同期
`garden/` の中身を Obsidian ボールトの Digital Garden フォルダへコピーする（1:1・上書き）。
構成が一致しているので、再コピーしても root に散らばったり重複したりしない。
（将来、Remote Control でボールトを接続できれば、Claude が直接書き込める。）

## 公開（Obsidian Digital Garden プラグイン）
- `dg-publish: true` のノートが公開対象。
- 公開は GitHub リポジトリへ push して行われるため、**プラグイン設定の GitHub トークン**が有効である必要がある。
- `github_pat_...`（fine-grained PAT）は**期限切れで publish が止まる**のが定番の落とし穴。
  - 失敗したら: GitHub で新しい fine-grained トークン（対象リポジトリに **Contents: Read and write**）を発行し、
    Obsidian → Digital Garden プラグイン設定の **GitHub token** に貼り替える。
  - トークンの実体は設定欄にだけ入れる（チャット等に貼らない）。
